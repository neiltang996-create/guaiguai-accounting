# AI 开发记录

## 人与 AI 如何配合

作者负责真实需求、产品取舍、设备授权和使用反馈。AI 参与代码、界面、测试、构建、问题排查与说明文档。开发并非全部自动完成，也没有把 AI 生成结果当成无需验证的事实。

早期使用 DeepSeek Harness；随后使用 Codex + GPT-6 Astra。早期效率未达到作者预期、转用后效率明显提高，是这次个人经历中的感受，不是控制变量实验，也不代表普遍模型排名。本地 Codex 会话 `turn_context` 记录到 `gpt-6-astra`。

典型循环是：描述一条可观察的行为 → 代码实现 → 单元或设备测试 → 两部手机试用 → 纠正识别、权限和交互问题。例如退款需要同时核对原月统计与实际到账余额，不能只检查表单有无按钮。

## AI 没有替代的工作

- 使用者仍需验证自动识别；拿不到微信节点和支付保护限制不能靠更强措辞解决。
- 财务不变量用测试验证：双人消费只扣一次、失败写入回滚、退款不虚增收入。
- 公开发布需独立隐私审查。不能把私人配置、日志或真实 CSV 当作“完整开发经历”直接上传。
- 没有旧 Git 就不伪造 commits。早期过程用故事和变更说明记录，并区分作者自述、代码证据与可核实日志。
